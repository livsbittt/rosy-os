Rosy OS Device runbook
=======================

This file is the canonical short runbook for the absorbed rosy_control package.
The historical standalone Control runbook is preserved in the workspace archive
and must not be used to install or start a robot.

Development checks (from the Rosy OS repository root):
  PYTHONPATH=src/rosy_control:src python3 -m pytest src/rosy_control/test/ -q
  PYTHONPATH=src/rosy_core:src/rosy_control:src python3 -m pytest src/rosy_core/test/ -q
  (PowerShell: set $env:PYTHONPATH to the semicolon-separated equivalent.)

Device prerequisites:
  - Raspberry Pi OS Lite 64-bit
  - network, time synchronisation, SSH, and Docker ready
  - signed immutable Rosy OS artifact and release manifest available

Install and verify one stationary Device:
  cd /opt/rosy/deploy/robot
  sudo ROSY_ROBOT_NUMBER=1 bash ./install-pi.sh
  sudo ./verify-pi.sh
  sudo ./runtime-mode.sh up
  sudo ./device-readback.sh --json

The installer owns ROS_DOMAIN_ID and ROSY_NAMESPACE. Never edit those identity
values by hand in .env. Keep the core profile stationary until readback proves
identity, active generation, immutable image digest, systemd/core health, ROS
graph health, and exactly one final cmd_vel publisher.

Promotion order:
  1. accepted stationary core and sensor-only evidence
  2. calibration generation/readback acknowledgement
  3. camera/OpenCV frame timing and quality
  4. motor UART, deadman, e-stop, stale-input, and stop-distance checks
  5. box/pallet payload and placement trials
  6. OMX model, mount, power, hand-eye, collision interlock, grasp/release,
     and recovery trials

A passing source test or image build does not promote a Device or FIELD gate.
Legacy nodes remain available for parity tests only; never run their final
publisher beside rosy_core.
